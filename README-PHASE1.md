`dev-pipeline.sh` builds a tiny busybox rootfs (init + s6 layout), packs erofs,
generates verity tree, assembles cmdline, signs payload — using a stub kernel file
for assembly testing. The Nix path (`nix build .#payload-qemu`) is the executed
pipeline with the real pinned kernel and is the reference flow.

## First real boot (Linux host with QEMU)

The Nix image pipeline is executed: `nix build .#payload-qemu .#kernel-qemu`
produces the complete signed payload (kernel, rootfs, verity, signed
manifest) deterministically, and it passes the gfx input gate in QEMU.

```bash
nix build .#payload-qemu .#kernel-qemu --no-link --print-out-paths
# then: tools/nix-payload-boot-gate.sh   (boots the Nix payload, runs the gate)
```

## Layout

- `kernel/` — config fragments (.config source of truth) + Nix structured mirror
- `system/` — stage-2 init, s6-rc service sources, rootfs derivation
- `targets/<device>/` — per-target payloads, firmware manifests, bringup docs
- `tools/` — pipeline scripts + harnesses (all runnable unprivileged)
