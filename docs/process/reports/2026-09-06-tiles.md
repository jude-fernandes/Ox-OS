# Dynamic shell tiles + ghost-window reap

Date: 2026-09-06
Status: **DONE — TILES GATE ALL GREEN** (installed package appears in
the home grid and launches from a tap; verdict at bottom)

## Scope

Phase 3 chunk 10: the packaging loop closes at the UX level. ox-shell
queries intentd's package list (`list` op) every time it draws the
home screen, filters out built-ins already on the grid, and renders
up to four dynamic tiles in the grid rows below (2-column layout
continued; in-window and 48 dp touch-target enforced by unit test).
A tap on a dynamic tile runs the same intent chain as a built-in.
intentd down ⇒ the grid degrades to the four built-ins (best-effort
by design). Second-order proof: the boot selftest already launched
Hello once, so the gate's tile tap exercises a *relaunch* (fresh
staging copy, fresh process, fresh reap).

Gate (`tools/tiles-gate.sh`): require `intent-install app=Hello`
BEFORE unlock (the tile must exist) → PIN unlock → tap the first
dynamic slot (center 158,483) → `shell-launch app=Hello` →
`intent-start` → screendump. Artifact: `2026-09-06-tiles.png`.

## The find: the ghost window became a device-unusable bug

First run: the gate could not unlock the device — three PIN attempts,
zero clicks reached the shell. The log showed the pad taps RAISING
window 6 instead of the shell: the boot selftest's Hello app had
exited 45 s earlier, but its window stayed on top forever, swallowing
every tap into a dead queue. The packaging report's documented honest
limit ("a crashed app would leave a ghost window") turned out to sit
exactly over the lock screen — an edge case promoted to a full blocker
by the very next chunk, which is precisely what gates are for.

**Fix (compositor lifecycle, not a workaround):** ox-ipc gained
`serve_with_disconnect` — a per-connection hook fired when a client
goes away (clean exit or crash). oxcom tracks the windows each
connection created (thread-local registry, pushed on `window-new`)
and the disconnect hook closes them through the standard window-close
path, journaling `client gone — its windows were closed`. This kills
the whole bug class: no app — exiting OR crashing — can ever leave a
surface that outlives it. The honest limit is retired.

## Honest limits

- The grid refreshes only on draw (unlock, launch). An app installed
  while the home screen is already showing appears at the next
  redraw; a live change notification is future work.
- No uninstall gesture in the UI yet (oxpkg remove works by CLI).
- Window-close on disconnect uses the compositor lock per window;
  a client with dozens of windows would reap serially (fine at this
  scale, noted for the multi-surface chunk).
