# Modem service layer — scoping and decisions (virtual target first)

Date: 2026-09-04/05
Status: **DONE — MODEM TRANSPORT GATE ALL GREEN** (transport + oxmodemd
service + SMS through the policy layer; verdict at the bottom)

## Why this is the biggest gap

Payments, graphics, power, and audio all have gate-verified service
layers. The modem — calls, SMS, mobile data — has nothing running yet,
and it is the component that makes the device a *phone*. It is also the
OS's single most charter-sensitive surface: the radio is the main
egress channel, so "no silent telemetry, ever" is enforced or lost
right here.

## Hardware facts (per docs/architecture/hardware-strategy.md)

| Target | Modem | Interface | Stack |
|---|---|---|---|
| PinePhone (CI fleet) | Quectel EG25-G (LTE Cat-4) | USB (2c7c:0125); QMI on /dev/cdc-wdm0, AT on ttyUSB2/3 | QMI via ModemManager/qmicli, or AT directly |
| Fairphone 5 (primary) | Qualcomm integrated (M.2-class) | QRTR/IPA + MBIM-ish | ModemManager over QRTR |
| Pixel 8a/9-class (study) | Samsung/Qualcomm integrated | AHB + RIL stack | hardest; IMS/VoLTE partial |

Consequence: the *transport* under the modem service differs per device
(USB-serial AT, QMI-over-USB, QRTR), so Ox needs a transport-agnostic
service boundary, not a one-modem script.

## Decisions

1. **Ox owns the modem service (`oxmodemd`), ModemManager is not the
   policy layer.** ModemManager may be consumed later as a hardware
   backend where it fits, but Ox's grant/egress model (per-destination
   grants, visible connections) must sit between apps and the radio.
   A ~small Rust daemon with explicit IPC is auditable in a way a
   D-Bus-centric manager is not.
2. **AT first, QMI second.** Every target modem above speaks AT for
   control; AT is line-based, trivially parseable, and testable against
   an emulator. QMI/MBIM add data-speed and voice-path benefits and
   arrive at the hardware phase per transport.
3. **Virtual target: virtio-serial is the "modem slot".** The virtual
   device never has a real radio (hardware-strategy: hardware claims
   never based on it). The slot is a named virtio-serial port
   (`oxmodem.0`), wired by the gate to a host-side AT emulator
   (`tools/modem-emu.py`, EG25-G personality) — the same substitution
   pattern as virtio-sound for audio. Kernel: `VIRTIO_CONSOLE=y`.
4. **SMS/data/voice sequencing.** Control-plane status (identity, SIM,
   signal, registration) first; SMS store/send second (emulator
   teaches +CMGS/+CMGR); mobile data (PPP or QMI bearer) and voice
   only against real modems on hardware.

## What is gate-verified (chunk 1 + 2)

`tools/modem-transport-gate.sh` proves, in one boot:

- kernel `VIRTIO_CONSOLE=y` → the named port (`oxmodem.0`) appears and
  is discovered via `/sys/class/virtio-ports/*/name` → devtmpfs node;
- **oxmodemd** opens the port as its single owner and runs the init
  poll (`AT+GMI/GMM/CPIN?/CSQ/CREG?`) through the AT engine —
  every command kmsg-journaled before it leaves (egress visibility);
- status over IPC via `oxctl oxmodemd refresh`: Quectel / EG25-G /
  SIM READY / CSQ 24,0 (−65 dBm) / registered — the full snapshot;
- an SMS is sent through the policy layer (two-phase CMGS; raw
  `AT+CMGS` via `cmd` stays refused) and the host emulator confirms
  receipt;
- the emulator log cross-checks the guest-side evidence both ways.

Milestones: `oxmodemd-up`, `oxmodemd-status-ok`, `modem-sms-ok`.

## Debug journey (what each failure taught)

1. First QEMU arg set: `-chardev socket,…,server=off,wait=off` — QEMU 8.2
   refuses `wait` in client mode; chardev never parsed, QEMU exited
   instantly. Fix: drop `wait`.
2. `virtconsole` ports are CONSOLE devices: the `/dev/vport4p0` node
   exists (devtmpfs) but open returns ENXIO — console ports are driven
   by hvc, not userspace. Fix: `-device virtserialport` → openable
   `/dev/vport4p1`.
3. Single-owner rule: with the selftest AND oxmodemd holding the port,
   the daemon's always-reading thread consumed the selftest's
   responses (emulator answered, guest saw nothing). Fix: the selftest
   now works only through IPC — the daemon is the modem's single
   owner, which is the product shape anyway.
4. `exec 3<>file` in the selftest: a redirection error on exec exits a
   POSIX shell silently (no milestone printed). Fix: per-exchange
   opens; failures flow into empty responses → honest failure
   milestones.
5. Daemon open-failure retry was a tight loop (kmsg spam ~4 ms); now
   backs off 2 s per attempt.

## Honest limits

- The emulator answers a fixed EG25-G personality; nothing about real
  RF, SIM auth, operator registration, or timing is claimed from it.
- No voice path, no data bearer, no SIM security (CHV) in the
  emulator yet.
- QEMU-only: no performance or RF claims (standing R-20 posture).

## Chunk 2: oxmodemd (the daemon)

`rust/crates/oxmodemd` — Phase-2 daemon in the same shape as powerd/
paymentsd (ox-ipc server at `/run/ox/sockets/oxmodemd.sock`, kmsg
logging, unit-tested pure logic).

- **AT engine**: reader thread → line queue; `command()` writes and
  collects lines until a V.250 final code (`OK` / `ERROR` /
  `+CME ERROR`) with a 5 s deadline; stale bytes drained per exchange.
- **URC policy**: explicit allowlist only (`RING`, `RDY`,
  `POWERED DOWN`, `+CMT:`/`+CMTI:`). A `+Cxxx:` prefix alone is NOT
  classified as unsolicited — `+CPIN: READY` is a response, not a URC.
  The set grows only with features that can emit those URCs.
- **Egress journal (charter)**: every radio command is kmsg-logged
  before it leaves the daemon ("at-command … (egress journal)").
- **Refusals**: interactive/traffic commands (`ATD`, `ATA`, `AT+CMGS`,
  `AT+CMGW`, `AT+CHLD`, `AT+CKPD`) and malformed input are refused —
  the daemon never half-supports a radio transaction.
- **IPC**: `status` (snapshot), `refresh` (poll identity/SIM/signal/
  registration), `cmd` (single gated AT command). `oxctl oxmodemd
  status` works through oxctl's generic daemon path — zero oxctl
  changes.
- **Resilience**: transport discovery (`/sys/class/virtio-ports/*/name`
  → devtmpfs `/dev/vportXpY`, `OX_MODEM_PORT` override for hardware
  later) runs in a thread; if the slot is absent the daemon stays up
  serving `transport:"missing"` (milestone `oxmodemd-up-noport`).
- **Status fields**: manufacturer, model, SIM state, CSQ + derived
  dBm (TS 27.007), registration, command/error counters, last error.

Gate integration: the guest selftest now finishes by querying the
daemon over IPC (`oxctl oxmodemd refresh`) and requires the discovered
model string in the reply — so one boot gates transport AND service.
