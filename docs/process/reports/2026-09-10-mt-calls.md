# Telephony: MT calls (ring/answer) — chunk 40, Phase 4, 2026-09-10

## Claim

Ox OS now RECEIVES voice calls end to end, closing chunk 37's honest-
scope gap ("MO calls only, no MT ring/answer"). The emulator gains
MT call injection through its control socket (`inject_call` -> the
radio raises `RING` every 2 s and reports the caller via CLCC); the
daemon's URC poller turns RING into a caller lookup (`AT+CLCC`, once
— repeats are deduped) and an honest `modem-ring` journal; the Dialer
app's callstatus poll raises an INCOMING banner + Answer button; and
answering goes through the same policy surface as dialing: the new
`answer` op consults permstored `telephony.dial` (deny refused, fake
= locally connected while the radio keeps ringing, grant = `ATA` on
the radio). The gate proves BOTH directions in one boot: the MO leg
still refuses under the bound deny (dial denied -> grant), then the
MT leg lands — RING -> `modem-ring` -> `dialer-incoming` -> Answer ->
emulator `CALL-ANSWER (was +15550003)` -> End -> `CALL-END (was
+15550003)` -> clean reap.

## Stack layers (all gated)

1. **Radio (emulator)**: `inject_call` control request (busy-refused
   if a call is out), a ring loop thread (RING @2 s while
   ringing), `ATA` (ringing -> active, `CALL-ANSWER` logged; ERROR
   otherwise), CLCC extended to MT states (ringing `state=4`,
   active `state=0`), hangup distinguishes declined-ringing
   (`CALL-DECLINED`) from ended-active (`CALL-END`).
2. **Service** (oxmodemd): `Call` gains `incoming`/`ringing`
   (MO construction sites updated); the poller's RING branch asks
   CLCC for the caller (RING carries no identity) and records the
   call + journals `modem-ring from=...` exactly once; the `answer`
   op (app-attributed, deny/fake/grant, journaled `modem-answer`)
   with a no-incoming-call guard; `callstatus`/snapshot now expose
   `incoming`/`ringing` so apps can render the truth. `parse_clcc`
   unit-tested (MT-ringing vs answered vs MO).
3. **App** (ox-dialer): ~2 s callstatus poll drives the MT UI —
   INCOMING banner (danger color) + Answer button while ringing;
   `dialer-incoming`, `dialer-answer-denied` (first refusal) and
   `dialer-call-active … incoming=true` journals; End doubles as
   decline for a ringing call and clears the banner either way.
4. **Verification**: mt-call-gate ALL GREEN (exit 0): install ->
   tile -> MO dial REFUSED (bound deny) -> selftest grant -> inject
   +15550003 -> emulator RINGs -> daemon CLCC + `modem-ring` -> app
   `dialer-incoming` -> Answer -> radio `CALL-ANSWER` +
   `modem-answer synthetic=false` + `dialer-call-active incoming=
   true` -> End -> radio `CALL-END` -> `dialer-call-ended` -> Close
   -> reap. Workspace tests green.

## Instructive findings

1. **A gate must wait for EMULATOR-side evidence with an
   emulator-log loop.** wait_ms greps the serial log only; the first
   draft checked `>> RING` (an emulator-log line) the instant after
   injection and failed before the 2 s ring tick ever fired. Same
   loop, different file: `wait_emu`. Related: `grep -aq` runs at
   wall-clock zero — any pattern that requires the guest to REACT
   needs a wait, never an instant grep.
2. **The pipeline eats the exit code.** The first rerun's "completed
   (exit 0)" came from `... | tail -30`: bash reports the LAST
   command's status, so a FAILed gate behind tail reads as success.
   The verdict line looked present until the log was actually read.
   Background runs now write to a file and echo `GATE-EXIT=$?`
   explicitly.
3. **RING carries no caller identity** — the standard demands the
   CLCC round-trip, which means the daemon's first-ring handler is a
   two-command transaction (CLCC then state) that must be deduped
   against the repeat RINGs; the emulator log shows exactly one
   `AT+CLCC` across dozens of rings.
4. **MT state lives in the same `Call` slot as MO** — dialing while
   a call rings is refused ("call already in progress"), which is
   correct no-call-waiting behavior, but it means gate authors must
   sequence MO-refusal BEFORE any MT injection or the refusal
   evidence comes from the wrong guard (chunk 39's ordering lesson,
   re-derived).

## Honest scope

- Answering while the permission is still deny is NOT exercised by
  the gate: the selftest grant flips during the MO leg, before any
  ring. The refusal path is the same mode_for/consult code the dial
  and sms-send refusals exercise; the app journals
  `dialer-answer-denied` when it happens.
- No in-call audio (no voice path on the virtual target — same as
  chunk 37); no call waiting (a second inject while a call exists is
  refused busy); declining a ringing call while DENIED would also be
  refused (hangup shares the dial permission) — user-hostile but
  consistent, noted for the permission-polish pass.
- Caller identity comes from CLCC at first ring; no CLIP-only path,
  no voicemail, no DTMF.
