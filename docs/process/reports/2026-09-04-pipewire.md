The server runs under s6 in the guest, creates its native socket, and
serves a real client round trip (`pw-cli info 0`). In-guest `pw-cli
--version` prints `Compiled with libpipewire 1.2.7 / Linked with
libpipewire 1.2.7` — proving the whole dynamic-linking path (PT_INTERP =
store musl, DT_NEEDED via baked RUNPATH, dlopen module search).

Sink node: `context.objects` adapter entry (`factory.name =
api.alsa.pcm.sink`, `api.alsa.card = 0`, `media.class = Audio/Sink`) —
node `ox-speaker` appears in `pw-cli ls Node` (verified in log dump).

## Integration knowledge baked in (reusable for every future dynamic guest)

- dlopen'd plugins are not tracked by the nix closure — copy their trees.
- Store-path copies land read-only: `chmod -R u+w` before overlaying.
- conf.d args values must be single-token (quoted multi-word values break
  the properties round-trip and kill the server with a confusing
  `usage: node.name=<string>`).
- `factory.name` (not `factory`), `api.alsa.card` (not
  `api.alsa.path="hw:0,0"` — the name can't resolve without a full alsa
  conf tree in-guest).
- alsa-ucm-conf exclusion is mandatory for the squashfs sort file.

## Playback — how it was solved

1. `adapter.auto-port-config` in the conf.d object creates the adapter's
   ports at load time (the step a session manager normally performs —
   found in pipewire's own `src/daemon/minimal.conf.in`).
2. The run script links a server-side `audiotestsrc` tone node
   (`pw-cli create-link`) to the sink input port; the graph runs and the
   tone flows pipewire -> ALSA -> virtio-sound -> host wav dump (45279
   frames, RMS 6834 — verified by the gate).

Note: pw-play (client stream) additionally requires session-manager
linking of client streams — deferred with WirePlumber to the hardware
phase. The gate proves the server, the graph, and the device path.

## Honest scope

- Gate runs on TCG QEMU; no performance claims (R-20).
- The OSS audio selftest (`audio-played`) remains the kernel→device proof;
  the pipewire gate adds the server + stream layer on top of the same
  virtio-sound device.
- No session manager (WirePlumber): the sink is declared statically.
  Dynamic device discovery arrives with the hardware bring-up phase, on
  real hardware where udev runs.
