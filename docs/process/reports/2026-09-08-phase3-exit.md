### 2. Permission bypass negative matrix green

`negative-matrix-gate.sh`: 10/10 bypass attempts refused in one boot —
1 permstored: unbound app reads deny · 2 notifd: unbound post ·
3 contactsd: unbound contacts · 4 locationd: unbound fix ·
5 messagesd: unbound messages · 6 corrupted package install ·
7 valid-manifest + wrong-signature install · 8 unpackaged app start ·
9 nonexistent app removal · 10 wrong PIN. Unit-level refusals run in
the workspace gate: ox-files path-sandbox escape (caught by the test
gate on its first runs), manifest validation, bin traversal, plus the
a11y and zeroization pins.

### 3. a11y runs pass for shipped flows

ox-ui enforces its own rules per build: `Screen::audit_contrast` walks
every composed screen (WCAG AA 4.5:1 normal / 3:1 large against the
real backdrop; found and fixed outline labels at 4.1:1 via the new
PRIMARY_TEXT token, regression-pinned), and `button()` refuses touch
targets below 48 dp in either dimension. Honest scope note: contrast,
targets and spacing are what a build can verify; screen-reader
semantics and focus order require a platform a11y tree that a
from-scratch display stack does not have yet — tracked with the
input-stack work, NOT claimed done.

## Deviations & honest caveats

1. **Data-at-rest encryption:** R-23 interim — /data is plain ext4
   data.img on the virtual target; LUKS2 unlock is hardware-gated
   (Phase 4/5 bring-up).
2. **Transport-level secret copies:** the IPC JSON layer holds
   transient PIN copies we do not own; zeroization covers everything
   the shell/lockd own. Phase-5 transport hygiene.
3. **Factory secrets are DEV-grade:** default PIN 1234, dev duress PIN
   9999, dev ed25519 signing key — user-chosen enrollment and key
   ceremony are Phase 5/11.
4. **Screen-reader semantics** (above) are tracked, not done.
5. **Nine report PNGs (2026-09-05/06) are black frames** — QEMU's
   screenshot surface dies with the first guest suspend/resume
   (root-caused 2026-09-07); superseded by in-guest compositor scene
   dumps. The textual kmsg evidence in those reports is unaffected.
6. Everything above is **virtual-scope**: real radios, GNSS, cameras,
   power measurements and verified boot on devices are Phase 4+.
