# Live activity panel — chunk 27, 2026-09-08

## Claim

The shell now has an **Alerts** panel: the user's notification history
is visible and dismissible from the home screen, not just momentary
banners. notifd already kept a bounded RAM history (32) with
list/dismiss/clear ops — this chunk surfaces it in the UI.

## How it works

- A third footer button (**Lock · Recents · Alerts**) toggles the
  panel; views remain mutually exclusive (opening one closes the
  other) and relock resets all of them.
- The panel renders notifd's list as two-line cards (title + body)
  with a **Clear** button per card → notifd `dismiss {id}` → immediate
  refetch + redraw so the card disappears at once. Card bodies are
  inert. The count is journaled on every draw
  (`shell-alerts-shown count=N`) — the gate's assertion surface.
- While the panel is open, notification changes refresh it through the
  same event/poll pipeline as the grid and switcher (5s self-heal
  cadence; notification changes don't push events — that's tracked
  polish).
- notifd is unreachable → the panel shows "no notifications" (best
  effort, never fatal).

## Gate evidence (`tools/alerts-gate.sh` ALL GREEN)

A boot selftest (`alerts-selftest`) grants itself `post-notification`,
waits for the notifd selftest to finish, **clears the history**, and
posts two notifications — making the panel count deterministic. The
gate then: unlocks → taps Alerts → requires `shell-alerts-shown
count=2` → taps Clear on card 0 → requires the dismiss + `count=1` →
taps Alerts to return home. Artifact:
`2026-09-08-alerts-open.png` — a compositor scene dump captured
in-guest at panel-open showing both cards (488,753 non-black pixels).

## Unit tests (workspace gate)

`alerts_button_and_clear_cards_resolve`: the Alerts button sits right
of Recents on the same footer row and is hittable; the Clear button
sits inside its card and wins over the inert card body; no hits on an
empty list or outside; card 1 stacks below card 0.

## Instructive finding

The first gate run failed on `count=3`: the notifd-selftest had posted
its own notification (test.app) before the alerts selftest seeded
theirs. Instead of hard-coding 3, the selftest now waits for the
notifd flow to finish and clears the history first — the count is
deterministic by construction, not by coincidence.
