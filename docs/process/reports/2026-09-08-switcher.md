# Switcher / recents — chunk 26, 2026-09-08

## Claim

The home screen now has a switcher: the user can see which apps are
RUNNING and close them from the UI — the last core piece of the app
lifecycle that previously required apps to exit on their own.

## How it works

- **Two triggers, one handler.** A footer **Recents** button (next to
  Lock) and a **top-left tap zone** (x<180, y<72). The tap zone exists
  because apps draw from (190,80) down — the shell's top-left strip is
  the only part of the home screen reachable while a full-screen app
  is open. Tapping either toggles the switcher (while it is open the
  trigger doubles as "back to home"). Both are journaled
  (`shell-switcher-open` / `shell-switcher-close`).
- **The running list is honest.** The switcher renders intentd's
  `running` table exactly as fetched at draw time — hit tests run
  against the list the user SEES, not a fresher fetch. An empty
  switcher says so. A package-set change while the switcher is open
  refreshes it via the same event/poll pipeline as the grid
  (`shell-switcher-refresh`).
- **Close = intentd `stop {app}`.** intentd SIGKILLs the child,
  **reaps it synchronously** (no zombie, and a quick re-launch sees a
  clean table), journals `intent-stop app=… pid=… ok=true`, and
  releases the app's wake locks on its behalf (`app-<name>`, both case
  variants — best effort; wake locks are ownerless strings in powerd,
  so a killed app could otherwise pin the device awake forever).
  Killing any app is safe with the compositor: the client disconnect
  hook reaps the dead app's windows.
- Tapping a card body (not Close) focuses/launches the app and returns
  home — intentd start is idempotent while the app runs.

## Gate evidence (`tools/switcher-gate.sh` ALL GREEN)

Unlock → launch Settings from its tile (it runs and covers the shell)
→ tap the top-left trigger → switcher lists the running Settings
**above the app's window** (the tap raised the shell window) →
Close on its card → assertions:

- `intent-stop app=Settings pid=… ok=true`
- `wake-lock-release id=app-settings` — the killed app's wake lock was
  released, not leaked
- `shell-app-close` + `shell-switcher-refresh`
- **no** `intent-exit app=Settings` afterwards: stop() reaps
  synchronously; an async exit here would mean a zombie (absence
  asserted over 8 s)
- Recents returns home; Settings relaunches cleanly afterwards
  (intent-start count grows)

## Instructive findings

1. **My first gate asserted a reap that cannot happen.** I waited for
   `intent-exit app=Settings` after the stop — but stop() reaps the
   child itself, so that milestone only ever appears for self-exiting
   apps. The gate now asserts the honest property instead: no
   `intent-exit` afterwards (no zombie).
2. **`ButtonVariant::Outline`, not `Outlined`** — the workspace gate's
   build caught the typo before it could ship.
3. The switcher trigger placement was a real UX decision: the footer
   button is undiscoverable while an app is open (apps cover it), so
   the always-reachable top-left strip carries the same trigger — the
   phone-pattern equivalent of a home gesture.
