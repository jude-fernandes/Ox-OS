# Networking groundwork — netd (interface bring-up, DNS forwarder, name policy)

Date: 2026-09-05
Status: **DONE — NETWORK GATE ALL GREEN** (twice: fresh payload +
confirmation boot)

## Scope

Phase 2 groundwork for netpolicy/dnsd, on the virtual target's
virtio-net (user-mode slirp). This milestone establishes:

- **Interface bring-up owned by a service**: netd raises loopback,
  configures the discovered interface (slirp defaults 10.0.2.15/24,
  gw 10.0.2.2 — deterministic on the virtual target; DHCP via udhcpc
  is the hardware-phase path where addressing varies), and points
  /etc/resolv.conf at itself.
- **dnsd function embedded in netd**: a UDP DNS forwarder on
  127.0.0.1:53. Apps resolve through it (the product path — netd's own
  self-test resolves exactly the way an app would).
- **Egress journal (charter)**: every query is kmsg-logged before it
  leaves — "dns journal <name> -> forward <upstream>".
- **Name policy**: runtime deny-suffix list (IPC-settable, file-seedable)
  enforced at the resolver — refused queries never leave the machine.
  A built-in canary (`*.refused.ox`) exercises the refusal path every
  boot. Per-app socket-level enforcement (netfilter/cgroup matching)
  is the Phase-2 remainder and is documented as such.

## Implementation

`rust/crates/oxnetd` (same shape as the other daemons: ox-ipc at
`/run/ox/sockets/netd.sock`, kmsg dual-channel, unit-tested pure
logic — query-name extraction, suffix matching, refusal builder,
A-record parsing). Milestones: `netd-up`, `netd-dns-ok`,
`netd-policy-ok`. Guest busybox provides ifconfig/route (no `ip`
applet); udhcpc exists for the hardware DHCP path.

Gate (`tools/network-gate.sh` + `tools/net-dns-emu.py`): boots with
`-nic user,model=virtio-net-pci` against a deterministic host DNS
responder on 127.0.0.1:53 (slirp aliases it at 10.0.2.2 — the guest
never depends on real internet). Cross-checks:

- `netd-up` → interface configured;
- `netd-dns-ok` → `ox-gate.test` resolved through the forwarder, and
  the host responder's log proves the query crossed;
- `netd-policy-ok` → `canary.refused.ox` refused in-guest, and the
  host responder's log proves it never crossed.

## Debug journey

1. `upstream` String moved into the forwarder thread, then reused by
   the IPC closure — rustc E0382; fixed with Arc.
2. **Loopback down**: ox-init never raises `lo`, so binding
   127.0.0.1:53 failed with EADDRNOTAVAIL and the self-test's UDP send
   got an instant ICMP refusal (failure 2.0 s after start — the instant
   timing was the diagnostic, a real upstream timeout would have been
   3 s later). Fix: netd raises `lo` itself.
3. Gate cross-check greps were written with the wrong quote style for
   python-repr log lines (caught before any rerun) — plus a leftover
   duplicate block from an earlier edit had to be removed.

## Honest limits

- Slirp user-mode networking: no real radio, no packet-level per-app
  enforcement yet, no throughput claims (R-20 posture).
- Refusal is resolver-level; a determined app with raw socket access
  bypasses it until the netfilter enforcement layer lands (tracked as
  the netpolicy remainder, not silently assumed).
- 10.0.2.2 DNS upstream is a gate convenience; DHCP-learned resolvers
  arrive with the hardware networking work.
