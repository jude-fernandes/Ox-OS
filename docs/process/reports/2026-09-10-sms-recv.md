# Messaging: SMS receive path — chunk 39, Phase 4, 2026-09-10

## Claim

Ox OS now RECEIVES real SMS end to end, closing chunk 38's honest-
scope gap. The emulator gains a control socket through which a gate
injects an inbound message; the radio raises the standard `+CMTI`
store notification; oxmodemd classifies the URC (including while the
line channel is idle — previously idle-time URCs sat unclassified
until the next command flushed them away), reads the message off the
store with `AT+CMGR`, keeps it in a daemon inbox, deletes it with
`AT+CMGD`, and journals the receipt. The Messaging app polls a now
permission-checked `sms-list` (the inbox is private, like sends:
deny refused, fake mode returns clearly synthetic entries) and
journals + draws each new arrival. The gate proves BOTH directions in
one boot: the send leg stays honest (bound-deny refusal -> grant ->
radio `SMS-SENT to +15550001: 'hi'`), and the receive leg lands
(`SMS-INJECT idx=1` -> `SMS-READ idx=1` -> `modem-sms-received` ->
app `sms-received from=+15550002 text=meet at the dock at 9` ->
`SMS-DELETE idx=1`).

## Stack layers (all gated)

1. **Radio (emulator)**: modem-emu.py gains `--ctl PATH` (control
   socket; JSON `{"inject_sms": ...}` -> stores the message, raises
   `+CMTI: "SM",<idx>`, queues if the guest has not connected yet),
   plus `AT+CMGR=<idx>` (header + body, `+CMS ERROR` when missing)
   and `AT+CMGD=<idx>`. All modem-socket writes now go through one
   lock (the control thread and the AT loop write the same socket).
2. **Service** (oxmodemd): `AtEngine::park_idle` classifies the raw
   line channel when no command is in flight (URCs parked, non-URCs
   returned loudly — nothing silently discarded); a 100 ms poller
   drains the parked URCs, and per `+CMTI`: CMGF, CMGR, parse
   (`parse_cmti`, `parse_cmgr_from` — unit-tested), record
   (monotonic daemon id, so SIM index reuse can't collide), CMGD,
   journal `modem-sms-received from=... text=...`. `sms-list` gains
   app attribution: deny -> `telephony.sms denied`, fake -> the
   snapshot's received list replaced by one labeled synthetic entry,
   grant/system -> the real inbox.
3. **App** (ox-sms): ~2 s inbox poll through the attributed read
   (during the deny phase the read is refused and the inbox stays
   honestly empty); new entries journal `sms-received from=... 
   text=...` and draw in an inbox line (count + latest, truncated).
4. **Verification**: sms-recv-gate ALL GREEN (see Claim); send leg
   re-proven in the same boot; workspace tests green (CMTI/CMGR
   parsers, inbox-line truncation).

## Instructive findings

1. **URCs only got classified while a command was in flight.**
   oxmodemd's reader thread pushes raw lines to a channel; the
   command loops classify them (finals end the command, URCs park,
   the rest is response data) — but the FIRST thing every command
   does is `try_recv`-flush "stale" bytes. A `+CMTI` arriving while
   idle therefore sat in the channel until the next command's flush
   threw it away: the receive feature would have looked broken at the
   radio layer while every test with a command in flight passed.
   `park_idle` drains the same channel on a 100 ms tick, parking URCs
   and returning leftovers loudly instead of discarding.
2. **Receiver expression vs argument borrow.**
   `st.received.push(RecvRec { id: st.recv_next, ... })` fails E0502
   (the push's mutable borrow is two-phase but the struct literal
   reads another field of `st` in argument position); binding the
   record to a local first is the idiom. Costs nothing, saves a
   rebuild cycle.
3. **BRE `+` is literal but `\+` is a quantifier.** The gate's first
   draft grepped `from=\+15550002`; under GNU BRE `\+` means "one or
   more of the previous character" (`=\+` = `from==`), which can
   never match `from=+...`. Plain `+` needs no escape in BRE.
4. **Store indexes are not identities.** The emulator's `+CMTI` index
   is reused after `AT+CMGD`, so the daemon assigns its own monotonic
   ids to inbox records; the app dedupes on those. Otherwise deleting
   message 1 and receiving a new one as index 1 would make the app
   treat it as already-seen.

## Honest scope

- Single-part, single-line inbound text (the store path has no
  multi-part concatenation; 160-byte printable-ASCII discipline
  applies at the sender side only).
- The inbox lives in oxmodemd; the Phase-3 messagesd synthetic-store
  contract is untouched — wiring the real inbox into messagesd (and
  delivery notifications through notifd, which needs the app to
  declare a notification permission) is future work.
- App attribution for sms-list/sms-send is still the payload's own
  `app` string (honor-system, journaled); sandbox-level attribution
  is on the roadmap.
- No read/unread distinction beyond the emulator's header (the
  daemon deletes after reading; per-conversation state is UI work).
