# ox-files gate + hashed PIN verifier (lock-screen security)

Date: 2026-09-06
Status: **DONE — FILES GATE ALL GREEN** (and the hashed PIN verifier
verified in the same run; verdict at bottom)

## Scope — two chunks, one gate

### 1. ox-files — the third packaged app, gated end to end

Directory browsing sandboxed to `/data/ox` (`..` components and paths
outside the root are refused and journaled as `files-refused`),
directories-first listing as cards (5 rows, "+N more" overflow),
tapping a file opens a read-only text view (18 lines), Up/Back climbs
out, Close exits. Same foreground-app wake-lock contract as the other
apps. Gate: PIN unlock → Files tile tap → `shell-intent app=Files` →
`intent-start` → `files-ready` → first-row tap → `files-open
path=/data/ox/lock.pin kind=file` → Back → `files-back` → screendump →
Close → `files-exit` → intentd reap. All legs first attempt.

### 2. Hashed PIN verifier — plaintext PIN removed from disk

The lock secret is no longer the plaintext file `/data/ox/lock.pin`
("1234"). It now stores `v1:<salt_hex>:<hash_hex>`:

- 16-byte salt from `/dev/urandom`,
- **4096 rounds of iterated SHA-256** (stretching makes offline brute
  force cost real time per guess; no new dependencies — SHA-256 comes
  from ox-pay-proto, RFC-vector-tested since the payments chunk),
- first boot enrolls the DEV default (1234) as a salted hash and
  journals it; a corrupted record re-enrolls (fail safe, not fail
  open);
- verification recomputes the stretched hash — constant-shape compare
  of digests.

Unit tests: accepts-only-the-right-PIN (incl. empty), salt diversity
changes the digest, store-format roundtrip, stretching-sanity
(iterated ≠ single hash).

## Verification

One gate run exercises both chunks: the gate's PIN leg unlocks with
1234 **against the salted-hash record** — the log line
`enrolled as salted hash` (first boot) plus `shell-unlocked` proves
the verifier end to end; the rest of the gate is the Files lifecycle.
Artifact: `2026-09-06-files-pin.png` (Files listing over the shell).

## Debug journey

- One rustc fix: let-chains (`&& let`) are E0658 on rustc 1.82 — the
  store parser was rewritten as nested ifs.
- One gate fix worth recording: the first run FAILED its open leg even
  though the log showed `files-open path=/data/ox/lock.pin kind=file`
  firing at the first tap — the grep pattern `name=files-open
  kind=file` doesn't match because the `path=` field sits between.
  The app was right; the test's assertion was wrong. Milestone greps
  should match on the milestone name and check fields separately.

## Honest limits

- Enrollment is still the DEV default; a user-chosen PIN flow (change
  on the pad, never a typed console secret) is the next security
  chunk. Secure enrollment (no plaintext PIN anywhere, ever) pairs
  with it.
- 4096 rounds of iterated SHA-256 is honest stretching but not a
  memory-hard KDF (Argon2id is the production target — needs a
  dependency decision).
- Files: no rename/move/delete yet (read-only browsing by design for
  this chunk); sandbox root is compile-time.
