# Accessibility pass — chunk 29, 2026-09-08

## Claim

The design system now ENFORCES its own accessibility rules, verified
at every build: WCAG AA contrast for every text token against its real
backdrop, and 48 dp touch targets in BOTH dimensions for every button.
One real violation was found and fixed.

## What the audit covers

- **Contrast (`Screen::audit_contrast`)**: walks a composed screen's
  ops; for every text op it finds the last opaque rect painted
  beneath the glyph anchor (thin accent strips ≤ 6 px are decoration,
  not backdrops) and computes the WCAG 2.1 contrast ratio — 4.5:1 for
  normal text (BODY/LABEL), 3.0:1 for large (TITLE/DISPLAY ≥ 24 px).
  No backdrop rect means the screen base (SURFACE). First violation is
  reported with both colors and the measured ratio.
- **Touch targets**: `Screen::button` now refuses width below 48 dp as
  well as height (previously height only — a 10×48 button would have
  passed).
- **Spacing grid**: SP steps stay multiples of 4 dp (existing token).

## The real finding

**Outline-button labels were 4.1:1 on true black** — the label used
the brand PRIMARY green (0x2E7D32), which as TEXT on the surface sits
below WCAG AA's 4.5:1 (as a FILL under white text it is fine: 5.1:1).
Fix: a new `PRIMARY_TEXT` token (0x81C784, 10.4:1 on black, 9.5:1 on
the navy surface-high) for primary-tinted text on dark surfaces; fills
keep the brand green. The failing pair is pinned by a test so it can
never silently return.

## Verification (workspace gate, run in every payload build)

- `contrast_math_matches_known_values` — black/white = 21:1,
  symmetry, self-contrast = 1.
- `plain_primary_as_text_on_black_fails_aa` — the regression pin:
  PRIMARY on SURFACE must stay below AA, PRIMARY_TEXT must clear it.
- `filled_and_danger_buttons_meet_wcaa` — white on brand green and
  danger red both ≥ 4.5:1.
- `every_text_on_a_representative_screen_passes_aa` — a screen
  exercising every component (top bar, tile, card, filled, outline,
  danger buttons, muted label) passes the auditor end to end.
- `thin_accent_lines_do_not_swallow_backdrop_audit` — the auditor
  sees panels behind accent strips.
- `buttons_enforce_width_and_height_targets` — narrow buttons refused.

Plus the ALERTS GATE re-run ALL GREEN against the updated toolkit
(no behavioral change; the outline Clear buttons now render in the
brighter, AA-compliant label color).

## Honest scope note

What this pass CAN verify: contrast, touch-target geometry, spacing
discipline — the measurable substrate of accessibility. What it cannot
(with a from-scratch display stack and no platform a11y tree yet):
screen-reader semantics, focus order, and TalkBack-style navigation.
Those are tracked with the input-stack work rather than claimed done.
