# Chunk 60 — Per-client ownership + op ACLs in oxcom

Date: 2026-09-26 (laptop-local Irish time)
Status: SHIPPED — workspace-test ALL GREEN, ACL GATE ALL GREEN, bt-gate
solo ALL GREEN on this tree (payload 5447iv8dq0s2bgrs4fl7d7miffbmvszc)

## Problem

Every oxcom op was callable by any connected client. The scene's own
header said it: "Interim trust model: any client may touch any window id
— per-client ownership lands with the Phase-5 security work." After
chunk 59, `window-secure` (the lockscreen shield) existed but any client
could call it — a compromised or buggy app could disengage the shield,
close the lock pad's window, or close/spoof other apps' surfaces.

## Design: ownership + one SYSTEM role, both kernel-of-truth free

- **Ownership** = the existing `CONN_WINDOWS` thread-local (the ghost-
  reaper's registry). A connection owns the windows it created. Chunk 60
  fixes a real flaw found by the tests: ownership previously attached
  only when the window's first PAINT succeeded — a window that errored
  painting (headless test, transient DRM failure) was unowned and
  unreapable. Ownership now attaches at CREATION.
- **SYSTEM role** = first claimant of the new `register-system` op (the
  shell, at boot). Held per-connection, freed by the disconnect hook
  when that connection dies (shell crash → next shell reclaims).
  Refusals journal `OXMILESTONE name=system-client-registered` /
  `acl-refused op=... win=... kind=...`.
- **The ACL table** (pure fn, exhaustively unit-tested):
  - `window-secure` → SYSTEM only (the shield is the trust anchor)
  - `window-close`, `window-commit`, `window-focus` → owner or SYSTEM
  - everything else (reads, own-window lifecycle, `window-new`) → open
- The disconnect reaper shares a new `close_window_core` with the op —
  the reaper legitimately closes its client's windows after the
  ownership registry is drained, so it bypasses the ACL by construction
  (the first design had the reaper call the op and would have re-refused
  every reap — caught on paper before it ran).

## Honest boundary (documented, not hidden)

- Read ops (`screendump`, `status`) and `window-new` stay open: gates and
  debug tooling use them today; restricting them needs a permission
  consult (permstored) — next slice.
- **Input-wait sniffing is still open**: a client can `click-recv` on a
  window it does not own (the app helper-connection pattern depends on
  this today). Closing it needs per-PROCESS identity (SO_PEERCRED), the
  next security chunk.
- The 0600 root-only socket remains the outer boundary; the ACL is
  defense-in-depth between guest processes, all of which run as root
  today.

  success, so display-less tests had unowned windows (and the ACL
  rightly refused their closes). Fixed at the handler (creation-time

- Test run 2: role-free leg failed — the test used `serve()` whose
  disconnect hook is EMPTY; the role-free lives in the real hook
