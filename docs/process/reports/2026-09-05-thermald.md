## Scope

Phase 2 "thermald": `rust/crates/oxthermald`.

- **Temperature sources**: milli-°C integers from a configured path.
  On hardware: `/sys/class/thermal/thermal_zone*/temp`. On the virtual
  target QEMU has no thermal zones, so the source is any readable file
  the gate drives (`OX_THERMAL_SRC=/tmp/ox-thermal/temp`) — the same
  substitution pattern as the modem and DNS emulators.
- **Policy tiers with hysteresis** (`HYST_OFF_MC` = 10 °C): a tier is
  entered on threshold, and left only once the temperature falls 10 °C
  below it — a hovering temperature cannot flap the policy.
  - warn (≥60 °C default) — notify
  - hot (≥75 °C) — throttle tier (hardware action: cpufreq clamp;
    virtual target journals the action)
  - critical (≥95 °C) — emergency tier (hardware action: orderly
    power-off path; virtual target journals)
- **Transitions journaled on escalation**, upward only, hysteresis
  transitions logged as "cooled".
- **IPC**: `status` (temp, state, thresholds, event counters),
  `config` (thresholds, strictly-ordered validation). Unit tests cover
  tier escalation and the hysteresis band (including the
  hover-below-threshold case).

## Gate

`tools/thermal-gate.sh` + `thermald-selftest` (event-driven — polls
IPC state after each step, no wall-clock assumptions, wake-locked):
sets thresholds 40/50/60 °C over IPC, then drives the source
25 °C → 42 °C (state 1) → 52 °C (state 2) → 62 °C (state 3) and
requires `thermald-tier-ok`. The gate greps the three escalation
milestones (`thermald-warn`, `thermald-hot action=throttle`,
`thermald-critical action=emergency`).

## Honest limits

- No thermal zones exist on QEMU: the *policy engine* (thresholds,
  hysteresis, transitions, IPC) is verified; real trips, cpufreq
  clamping, and power-off actions are hardware-phase work.
- Default thresholds (60/75/95 °C) are typical smartphone values, not
  measured device limits.
