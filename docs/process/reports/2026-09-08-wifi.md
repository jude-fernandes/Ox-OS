# Wi-Fi bring-up — chunk 31, Phase 4 opens, 2026-09-08

## Claim

Ox OS runs the REAL wireless stack end to end on the virtual target:
kernel cfg80211 + mac80211 with mac80211_hwsim virtual radios,
hostapd running a WPA2-PSK AP on one radio, wpa_supplicant
associating on the other — and an ICMP ping crossing the
authenticated 802.11 link inside the VM. Nothing is mocked: the
userspace daemons are the same ones real hardware runs; only the
radio is virtual. On devices, the same wpa_supplicant talks to real
chipsets through the same nl80211 interface.

## Stack layers (all gated)

1. **Kernel** (fragment in `kernel/kernel.nix`): CFG80211, MAC80211,
   MAC80211_HWSIM as modules; link crypto (CCMP/GCM/CTR/GHASH/
   MICHAEL_MIC/ARC4) built in. Boot cmdline
   `mac80211_hwsim.radios=2` → exactly two radios (wlan0 client,
   wlan1 AP). The four `.ko` files are xz-decompressed at build time
   into the rootfs (`wifi-modules` derivation) — busybox insmod
   cannot read compressed modules.
2. **Daemons**: hostapd (AP on wlan1, ssid `ox-virt-ap`, WPA2-PSK
   CCMP) and wpa_supplicant (client on wlan0, pre-provisioned with
   the same network) as s6 longruns, full store closures shipped
   (libnl + openssl).
3. **Verification** (`tools/wifi-gate.sh` ALL GREEN): interfaces
   appear → WPA2 association `wpa_state=COMPLETED` → static addresses
   on both ends → **ping 10.10.0.1 across the authenticated link** →
   `wifi-stack-ok`.

## Instructive findings (the cost of doing this honestly)

1. **kconfig cannot force =y over a select target.** Forcing
   `CFG80211 = y` made nixpkgs' interactive config generator reject
   the answer mid-flight (cfg80211 `select`s CRYPTO_SHA256, which the
   base config has as `=m`; a y-answer would upgrade a select target
   and the script loops "repeated question" until EOF). Module form
   avoids the conflict entirely.
2. **Kernel modules ship xz-compressed** (`mac80211.ko.xz`); the
   first `wifi-modules` derivation found nothing because it globbed
   for `*.ko`. Decompress at build time with xz.
3. **insmod is order-sensitive** — the alphabetical glob loaded
   cfg80211 before rfkill ("Unknown symbol rfkill_*"), and mac80211
   failed on `arc4_setkey` until `CRYPTO_ARC4=y` joined the fragment.
   The selftest now loads rfkill → cfg80211 → mac80211 → hwsim in
   explicit dependency order.
4. **A 6-way parallel kernel compile can hard-crash the WSL VM**
   (connection refused mid-build; memory-pressure suspect). Build now
   runs at 4 cores — no crash since, negligible wall-clock cost.
5. `nix flake show` is not a cheap eval check: it starts BUILDING
   outputs. Removed as a pre-flight step.
