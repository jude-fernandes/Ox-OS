# Wi-Fi: the join flow (credentials behind permission) — chunk 42, Phase 4, 2026-09-10

## Claim

Ox OS ships NO factory Wi-Fi credentials anymore. wpa_supplicant
boots with an EMPTY network list — the client sits honestly
DISCONNECTED until a join is granted. oxwifid gains the `connect`
op behind a NEW permstored permission (`wifi.join`, sibling of the
existing `wifi.scan`): deny refused, fake = a join response labeled
synthetic:true while the radio NEVER sees the PSK (wpa_state stays
DISCONNECTED, proven), grant = real provisioning through wpa_ctrl
(ADD_NETWORK + SET_NETWORK ssid/psk + SELECT_NETWORK) and a REAL WPA2
association — confirmed on BOTH ends: the client's
`wpa_state=COMPLETED` and hostapd's own `AP-STA-CONNECTED` on the
AP-side virtual radio, with ICMP crossing the authenticated link.
The legacy gate greened unchanged in its milestone names; its
assertions grew the three honest-leg checks. PSKs are never
journaled — only the ssid.

## Stack layers (all gated)

1. **Daemon** (oxwifid): `connect {app, ssid, psk}` — consults
   permstored `wifi.join` (journaled), deny -> refused; validation
   (printable-ASCII ssid 1..=32, psk 8..=64, no quotes/control
   chars — they would break wpa_ctrl quoting; unit-tested); fake ->
   `wifi-join-synthetic` journal + synthetic response, zero radio
   I/O; grant -> `WpaCtrl::provision` (command construction
   unit-tested) + a bounded 25 s COMPLETED wait -> `wifi-joined
   ssid=… synthetic=false` journal. The PSK never appears in any
   journal.
2. **Config** (rootfs): wpa_supplicant.conf shrinks to
   `ctrl_interface` + `ap_scan=1` — the factory `network={}` block
   is DELETED; the hostapd.conf dev PSK remains (the AP side is the
   test fixture, not the credential holder).
3. **Selftest** (wifi-selftest, rewritten as the matrix walker):
   boot state asserted DISCONNECTED (`wifi-no-factory-join`) ->
   deny refused (`wifi-join-denied-ok`) -> fake answered synthetic
   with the radio still clean (`wifi-join-fake-ok`,
   `wifi-join-fake-radio-clean state=DISCONNECTED`) -> grant ->
   association (`wifi-associated ssid=ox-virt-ap` — LEGACY milestone
   name preserved so the legacy gate passes unchanged — plus
   `wifi-join-grant-ok`) -> ping across the link (`wifi-ping-ok`,
   `wifi-stack-ok`) -> scan through the daemon (`wifi-scan-found`)
   -> restore deny.
4. **Radio-side evidence**: hostapd/run now redirects to the console
   with `-d`, so `wlan1: AP-STA-CONNECTED` from the AP's own process
   on the OTHER virtual radio is in the gate's log — the association
   is proven by two independent processes.
5. **Verification**: wifi-gate ALL GREEN (RC=0) — the legacy
   assertions (iface, association, ping, stack, scan, Settings
   panel) plus the three new honest-leg checks, on a payload whose
   client boots credential-free.

## Instructive findings

1. **A stale flake source snapshot can poison a build with CRs that
   "are not there".** The rootfs build failed with `$'\r': command
   not found` inside stdenv setup while every file checked clean.
   The derivation env (found via `nix show-derivation` + a python
   `chr(13)` scan) really contained CRLF in buildPhase — from an
   eval that had consumed the pre-sync CRLF file — while the
   on-disk file was already LF. An explicit rebuild cleared it. Two
   sub-lessons: (a) the debug tooling must be more trustworthy than
   the system under test — my `grep -c '\r'`/`od | grep '\\r'`
   checks were mangled by shell-quoting layers into counting lines
   containing the LETTER r (558 "hits"), sending the hunt in
   circles; the only readings that mattered came from python byte
   counts. (b) The Windows-side rootfs.nix carried 374 mixed CRs
   (Edit-tool lineage) — normalized to LF so the ambiguity cannot
   return.
2. **Deleting factory credentials changes BOOT semantics, not just
   permission semantics.** The legacy milestone `wifi-associated`
   used to fire at ~boot+30 s unconditionally; now it only fires
   after the selftest's grant leg, which added deny+fake round-trips
   in front. The legacy gate's wait budget (60x2 s) would have been
   borderline — the associated wait got 150 iterations. When a
   milestone's MEANING survives a chunk but its TIMING moves,
   re-audit every wait that consumes it.
3. **SELECT_NETWORK is the whole join.** One wpa_ctrl call both
   enables the new network and disables every other — a v1 with
   exactly one credential slot, matching the one-AP fixture. A
   future multi-network store (with remembered-credential gating per
   network) grows this into a list, not a flag.
4. **Radio-side evidence needs the radio's own log.** The client
   saying COMPLETED is one process's claim; redirecting hostapd to
   the console (with `-d` for MSG_INFO) put the AP's
   `AP-STA-CONNECTED` in the same serial log the gates already
   read — two independent processes must agree before a gate calls
   a link real.

## Honest scope

- Exactly one runtime credential slot (SELECT_NETWORK replaces the
  previous join); no persistence across reboot (the provisioned
  network lives in wpa_supplicant's runtime state) — the credential
  STORE (remembered networks, per-network grants, sync) is future
  work on the roadmap.
- The dev PSK (`oxdevpass1`) is a fixture on BOTH sides (hostapd.conf
  plaintext is the AP's own config); nothing about the join flow
  depends on its value.
- Fake mode answers the join op only; the status op keeps serving
  the REAL radio state (granted apps see DISCONNECTED even while a
  synthetic join is "held") — the synthetic join exists only in the
  op's response and journal.
- No 802.11u/enterprise, no scanning-on-join (ap_scan=1 passive
  flow), no background rejoin after suspend — PM interplay is
  untested for joins.
