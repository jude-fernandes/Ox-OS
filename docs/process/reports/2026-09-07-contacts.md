# contactsd — fake-data providers, the charter's honest-permission feature

Date: 2026-09-07
Status: **DONE — CONTACTS GATE ALL GREEN** (deny/fake/grant all
verified; verdict at bottom)

## Scope

Phase 3 chunk 20: the third permission mode gets a real consumer. The
charter promises "fake-data permissions" — apps keep working while the
user's real data stays home. `ox-contactsd` is the first service to
deliver that contract:

Every `list {app}` consults permstored for `contacts.read`:
- **deny** (the default — including unbound apps and an unreachable
  permstore) → refused;
- **fake** → three synthetic contacts (`Fake Alice/Bob/Carol`,
  +1-555-01xx) flagged `"synthetic": true` — plausible shape, obviously
  not real people, and the response ADMITS it is synthetic;
- **grant** → the real store (`/data/ox/contacts.json`, empty on a
  fresh device — the user adds contacts later).

Every consult is journaled with the mode served
(`contacts-consult app=… mode=…`), so the audit trail records exactly
what any app was ever shown.

No new dependencies; oxctl's generic daemon passthrough
(`oxctl contactsd list '{…}'`) drives it with zero CLI changes.

## Gate

`tools/contacts-gate.sh`: requires `contactsd-ready`, then the boot
selftest's three-mode walk for app `contacts.test` — every consult
journal line (deny, fake, grant) plus `contacts-test-ok`. The fake
leg's DBG line in the log shows the actual served payload:
three synthetic contacts, `synthetic:true, count:3`.

## Honest limits

- contactsd serves the store read-only; add/edit/delete contacts is
  the app-UI chunk.
- One provider (contacts) exists; the pattern is now established and
  each future data service (location, messages) plugs into the same
  permstored consult + fake/grant/deny shape.
- The fake data is static; randomized-but-stable-per-app synthetic
  identities would resist correlation better (tracked).

## Verdict

**CONTACTS GATE ALL GREEN** (2026-09-07): deny refused, fake served
synthetic, grant served real — all journaled, all through the same
permission store the grants panel manages.
