## 1. Wi-Fi association — SOLVED

Root cause (chunk 51's bisect said "environment"; the precise shape):

- **hwsim assigns per-radio default channels** (radio0=2412/ch1,
  radio1=2437/ch6). The AP sat on ch6 — every client auth needed a
  remain-on-channel window whose response, under TCG load, regularly
  missed the client. With the AP moved to **channel 1 (the client
  radio's home channel)** the whole exchange is on-channel:
  association completed first-try, twice, including inside sweep9.
- Verified green twice on the final config (solo + sweep9), both boots
  each time (association + persistence + autojoin + forget).
- The chunk-51 confusion is documented honestly: the first channel-1
  attempt DID fix association (the serial showed the 4-way handshake
  completing) but the same run failed later at a Settings tap from
  stray-window clicks — the revert threw away a working fix.

Also in the final wifi config: `iw` now ships in the rootfs (closure
pattern), the wifi selftest dumps radio state (`DBG-WIFI-FAILSTATE`) and
runs 4 full re-join cycles (user retry semantics) before any failure
verdict, and the gate reads the selftest's verdict generously.

## 2. Pad-entry hardening (the last failure class)

Sweep9's three failures shared one mechanism: **lagging clicks from the
PIN-unlock queue deliver up to ~100s after unlock**, and some land inside
the freshly opened app's pad — corrupting the number/recipient state
silently (e.g. `dialer-key c=9 num=9` before the '+' key, which is
empty-only and then can never fire; `sms-key c=1 len=2` before the
gate's first expected digit).

Fixes (in the payload + gates):
- **Per-keypress journals with full buffer state**: ox-dialer journals
  `dialer-key c=<k> num=<number>` (and `c=C num=` for clear); ox-sms
  journals `sms-key c=<k> to=<recipient>` for the pad, `sms-key c=<k>
  txt=<text>` for the keyboard, `c=C to=` for clear. Unit tests updated.
- **Gates tap causally against the full state** (`tap_key … "to=+15"`):
  a tap is only accepted when the journal shows the exact expected
  buffer state, so lag-duplicated or stray presses cannot silently
  cascade.
- **Atomic restart cycles**: '+1' (and '+' alone where used) entered as
  C→+→1 cycles that restart from C until the journal shows the exact
  head state; digit entry as a whole restarts from C when the FINAL
  number journal ≠ the target (count-based "tap landed" checks, 3
  rounds) — lag-duplicated presses are tolerated by construction and
  the radio legs still assert the exact number/recipient.
- 120s post-unlock drain (the PIN queue can take ~100s+ to fully
  deliver) + the double-Close hygiene tap.

## 3. Environment limit (honest)

The validation runs for fix-set 2 repeatedly failed on ENVIRONMENTAL
noise, each with evidence: a zombie QEMU holding the VNC port (new QEMU
refused to start), WSL VM degradation (guest boot >600s real after ~1h
of continuous churn — the gate's fixed real-time budgets expire), an
orphaned process SIGTERMing a live run's QEMU, and QMP connection
refusals against a dead socket. A VM bounce restores ~1-2 clean hours.
The gates' budgets are real-time; **the structural fix is guest-time
budgets** (parse kernel timestamps from the serial and budget in guest
seconds) — Phase-5 hardening candidate, designed and scoped, not yet
built.
