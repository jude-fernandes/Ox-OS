# oxwifid + Settings Wi-Fi panel — chunk 32, 2026-09-08

## Claim

Wi-Fi is now a first-class Ox service: **oxwifid** serves scan/status
over Ox IPC with the charter's honest permission modes, and the
Settings app renders the live results in a Wi-Fi panel. Gate-proven:
a granted Settings scan lists the in-VM AP (`ox-virt-ap`, WPA2), and
the Settings panel shows `status=COMPLETED ox-virt-ap`.

## oxwifid

- **Transport**: minimal wpa_ctrl client — UNIX DATAGRAM to
  `/run/wpa_ctrl/wlan0`. Key protocol finding: the UNIX ctrl
  transport is **UNFRAMED** — the whole datagram is the command, the
  whole reply datagram is the text (a length-prefixed command is
  answered with "UNKNOWN COMMAND"; verified by hexdump). Unsolicited
  event notifications (`<3>…`) are skipped.
- **Honest permissions** (permstored, fail-closed): `wifi.scan` gates
  scan/status — deny refused, **fake** = synthetic network list
  (`Fake-Net-555xx`, synthetic:true — scan results are location
  data), grant = real results. Every consult journaled
  (`wifi-consult app=… op=… mode=…`).
- `connect {app, ssid, psk}` (gated by `wifi.control`) is the next
  increment; credentials belong in the credential store, not a config
  file — noted for the security phase.

## Settings Wi-Fi panel

A Wi-Fi button (fourth action, verb code 5) opens the panel: a status
line (wpa_state + ssid) and one card per scanned network with signal
strength. Draws are journaled (`wifi-panel-shown networks=N
status=…`) — the gate's assertion surface. Rows are informational;
PSK entry arrives with the credential store.

## Instructive findings

1. **wpa_ctrl UNIX transport is unframed** — replies are bare text
   datagrams; a length-prefixed request yields "UNKNOWN COMMAND"
   (hexdump-diagnosed: reply bytes `55 4e 4b 4e…` with no prefix).
   The length-prefixed framing exists only in the Windows named-pipe
   transport.
2. **Escape sequences through heredoc+python layers** silently became
   literal tabs/newlines (`\t` → TAB), breaking a char literal three
   separate times. WSL-side file edits now verify with `cat -A`.
3. **The WSL VM crashed twice** under 6-way parallel kernel compiles;
   4 cores is stable. The crash also corrupted nix's eval cache and
   store DB state ("don't know how to build" for valid drvs) —
   `wsl --shutdown` + rebuilding from a WSL-native tree copy
   (/root/oxbuild) cleared it. /mnt/c (9p) source reads can serve
   stale content to nix after a crash; WSL-native builds avoid that.
